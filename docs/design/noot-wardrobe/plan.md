# Noot wardrobe

Task: outfit Noot through a game menu ordered head to foot, replace simultaneous option grids, broaden actual 3D fashion and colors. Existing name validation, local persistence, multiplayer appearance broadcast, focus trap, reduced motion, and solo design tokens stay authoritative. No purchases, inventory scarcity or account sync are implied.

Research: Fall Guys' official about page separates colors, patterns and costumes (https://www.fallguys.com/about?lang=en). Nintendo's style video frames clothing as self-expression (https://play.nintendo.com/media/videos/animal-crossing-new-horizons-show-your-style-video/). Clothing references are ribbed cardigan hems (https://www.uniqlo.com/us/en/products/E450510-000/00) and contrast-sleeve varsity jackets (https://www.adidas.com/kw/en/originals-varsity-jacket/IA2398.html). Original geometry, no copied brand marks or product assets.

Same content for three functional hypotheses: live character, four categories, five representative outfit names, colors, angle controls, name, return action.
A: head-to-foot rail beside preview; compact outfit controls right on desktop and underneath on mobile. Spatial category mapping keeps Noot primary. Requires a deliberately short item row on mobile.
B: category bar above split preview/list. Item labels easy to scan but tall scrolling competes with character at narrow widths.
C: preview, category bar, carousel vertically stacked. Touch-friendly but the preview and action are farther apart and head-to-foot meaning is weaker.
Provisional choice A. 8px spacing with 4px half steps; stable preview/rail alignment; 44px minimum targets; existing Open Runde controls and Instrument Serif title. Category and item state replace content immediately; camera rotation uses current existing scene interpolation. No decorative panel animation is needed.

Working prototypes: /tmp/noot-wardrobe-study/index.html. Wireframe → typography → surface controls preserve three layouts. Reviewer is the implementing assistant; fresh-context/sub-agent comparisons are unavailable in this side conversation. Compare A/B/C and C/B/A without claiming independent review.


## Comparison and final implementation

A/B/C wireframes and type revisions were inspected in the in-app browser at 1280×720. C pushed item selection below the first viewport; B added category-bar height without the head-to-foot spatial relationship. Reversed C/B/A surface comparison retained A. At 390×844, the implementation refines A into a fixed preview and footer around an independently scrolling options pane. No independent reviewers were available; these are one assistant's observations, not a user acceptance score.

Three Blender-authored tops (cardigan, varsity, overalls) and two shoe styles (sneakers, ankle boots) are in assets/noot/fashion.blend. The active Noot Studio Blender scene and original GLB were preserved. Exporter: scripts/blender/noot_fashion.py, invoked through Blender MCP. Overalls were repaired after back-view inspection: straps now follow the body surface around the sides, with a raised front bib. Maximum added active geometry is 10,832 triangles / 5 draw calls for varsity + boots. Immutable geometry is shared and decoded by selected style; each Noot owns its material colors and uses its existing skeleton. Clothing + shoes are independently equipped.

22 named colors plus strict 6-digit custom hex values; independent hat, clothing, and shoe colors. Old profiles without new keys retain their previous linked color until edited. Hats keep plain fabric while clothing patterns are changed. New fields are accepted by the same shared multiplayer parser. Local storage failure retains the session outfit and shows a session-only status; retrying storage updates that status even for the same outfit. Outgoing picker edits are coalesced over 120ms and reconnect sends the latest full appearance.
